Services KB-002

Doc Transport Service Not Starting

The RightFax Document Output (Doc Transport) service handles outbound fax delivery and is one of the most failure-prone services in the stack. When it fails to start, outbound faxing stops entirely. Root causes range from a commonly overlooked Brooktrout board protocol toggle to AV interference and firewall misconfigurations.

Indicators
  • Doc Transport service in a stopped or error state in the RightFax admin console
  • Outbound faxes queue but are not transmitted, queue grows without processing
  • Windows Services shows the Doc Transport service fails to start with a generic error
  • Event Viewer logs show Brooktrout driver initialization failures or port binding errors
  • SIP connectivity established at the network level but RightFax cannot initiate calls
Diagnostic Checklist
01
Check the Brooktrout Configuration: TCP/UDP Protocol Toggle
This is the most commonly missed cause. In the Brooktrout SDK Configuration Utility, navigate to the SIP transport settings for the configured board. There are explicit toggles to enable TCP transport and enable UDP transport. If your SIP trunk uses TCP (common in enterprise SBC deployments) and TCP is set to disabled in the Brooktrout config, the service will not start. The same applies for UDP. Verify the correct protocol is enabled and matches your SIP infrastructure. This setting is distinct from Windows Firewall rules. The port can be open at the OS level and the service will still fail if the Brooktrout protocol toggle is off.
02
Verify AV Exclusions Cover the Doc Transport and Brooktrout Components
Brooktrout driver files and the Doc Transport executable must be included in AV/EDR exclusions. If exclusions were applied post-installation, a quarantine event during an earlier startup attempt may have flagged components. Check the AV quarantine log and restore any flagged Brooktrout or RightFax Doc Transport files, then retry the service start.
03
Confirm Firewall Ports Are Open
The Doc Transport requires network access to the SIP gateway or Session Border Controller. Required ports typically include:
  • SIP signaling: UDP/TCP 5060 (or 5061 for TLS-SIP)
  • RTP media: UDP 10000-20000 (range varies by Brooktrout configuration)
Verify these ports are permitted outbound from the RightFax server in both Windows Firewall and any network-layer firewall between the server and the SBC.
04
Verify the SIP Gateway Is Reachable
Confirm the RightFax server can reach the SIP gateway or SBC by IP and that the gateway is accepting registrations. A SIP trunk that has expired or a gateway that has been reconfigured (IP change, authentication change) will cause the Doc Transport to fail initialization. Test connectivity using a SIP test tool or by reviewing SBC logs for registration attempts from the RightFax server IP.
05
Review RightFax Doc Transport and Brooktrout Logs
RightFax maintains detailed logs in the configured log directory. The Doc Transport log and Brooktrout log will contain the specific error at the point of service failure. Common entries include port binding failures, SIP registration rejections, license validation errors, and Brooktrout driver initialization codes. These logs are the fastest path to a definitive root cause when the checklist steps above have not resolved the issue.
06
Check Service Account Permissions
The RightFax services run under a service account that must have appropriate local permissions on the server. If a password change has occurred on the service account, or if a group policy change has modified local rights (particularly "Log on as a service"), the Doc Transport will fail to start. Verify the service account credentials and local security policy assignments in the Windows Services configuration and Local Security Policy.
Field Note
The Brooktrout TCP/UDP protocol toggle is easy to overlook because it exists inside the SDK configuration utility rather than in the RightFax admin console, and because the error it produces (service not starting) is generic enough that most diagnostics go straight to firewall and AV checks. Always include the Brooktrout protocol configuration as step one when the Doc Transport fails to start in a SIP environment. Confirming the protocol toggle takes two minutes; the other steps can each take significantly longer.
